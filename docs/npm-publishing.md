# NPM Package Generation & Publishing Guide

This document details how the `@argela-uxui/ngx-query-builder` package is generated, packaged, tested, and published to the npm registry.

---

## 1. Package Architecture & Identity

The repository is structured as an Angular workspace containing both the library and demo applications:

| Entity | Location | Scope / Visibility | Purpose |
|---|---|---|---|
| **Root Workspace** | `/` (`package.json`) | `ngx-query-builder` (`private: true`) | Developer tools, workspace scripts, CI tasks, dependencies. **Never published to npm.** |
| **Library Source** | `projects/ngx-query-builder/` | `@argela-uxui/ngx-query-builder` | Source code for the Angular 22 library. |
| **Publishable Output** | `dist/ngx-query-builder/` | `@argela-uxui/ngx-query-builder` (`public`) | Compiled bundle generated by `ng-packagr` that gets published to npm. |

### Registry Configuration

The library's `projects/ngx-query-builder/package.json` defines publication settings:
```json
{
  "name": "@argela-uxui/ngx-query-builder",
  "publishConfig": {
    "access": "public",
    "registry": "https://registry.npmjs.org/"
  }
}
```

The workspace `.npmrc` maps the `@argela-uxui` scope and defines the local tarball output directory:
```ini
@argela-uxui:registry=https://registry.npmjs.org/
pack-destination=publish
```

## 2. Prerequisites & Credentials

To publish a release, ensure you have:

1. **Node.js & npm:**
   - Node.js `^22.22.3`, `^24.15.0`, or `>=26.0.0`
   - npm 10+
2. **Access Rights:**
   - An npm account with publishing/write permissions to the `@argela-uxui` organization on npmjs.com.
3. **Authentication:**
   Verify your authentication status from the command line:
   ```bash
   npm whoami --registry=https://registry.npmjs.org/
   ```
   If not logged in, authenticate:
   ```bash
   npm login --registry=https://registry.npmjs.org/
   ```
   *(Note: npm may prompt for Two-Factor Authentication / OTP).*

## 3. Pre-Release Quality Gates

Always ensure the codebase passes all automated verification before cutting a release:

```bash
# 1. Clean install of locked dependencies
npm ci

# 2. Run the full CI validation suite
npm run ci
```

`npm run ci` runs:
1. `npm run lint`: ESLint across library (`lint:lib`) and demo (`lint:demo`).
2. `npm run test`: Jest unit tests for the library.
3. `npm run e2e`: Playwright end-to-end tests against Chromium.
4. `npm run build`: Production library build via `ng-packagr`.

## 4. Versioning Strategy

`@argela-uxui/ngx-query-builder` follows [Semantic Versioning (SemVer)](https://semver.org/):
- **MAJOR (`X.0.0`)**: Incompatible API changes, breaking architectural changes, major Angular framework upgrades.
- **MINOR (`0.X.0`)**: Backwards-compatible new features, new directives, new options.
- **PATCH (`0.0.X`)**: Backwards-compatible bug fixes, minor performance improvements.

### Updating Version Numbers

When releasing a new version, synchronize the version field across:
1. `projects/ngx-query-builder/package.json` (authoritative package version)
2. `package.json` (workspace root version)
3. `CHANGELOG.md` (document changes under the release header)

> **Important:** npm will reject publishing if the version already exists in the registry.

## 5. Building the Package

To compile the library into the publishable format:

```bash
npm run build
```

Under the hood, this executes:
```bash
ng build ngx-query-builder --configuration production
```

### Why Partial Compilation Matters
Angular libraries are distributed using Angular's **Partial Compilation Mode** via `ng-packagr`:
- `projects/ngx-query-builder/tsconfig.lib.prod.json` sets `"compilationMode": "partial"`.
- This creates portable bundles that can be consumed by applications using any compatible Angular compiler version.
- **Do not publish development builds:** Development/watch builds (`npm run build:watch`) produce full-compilation output containing safety checks that actively block npm publication.

The compiled package artifacts are output to `dist/ngx-query-builder/`.

## 6. Testing & Inspecting the Package Before Publishing

### A. Dry-Run Publication
Inspect what npm would publish without actually uploading anything:

```bash
cd dist/ngx-query-builder
npm publish --dry-run
cd ../..
```

**Check the dry-run output for:**
- Package name: `@argela-uxui/ngx-query-builder`
- Version: Matches your target release version
- Registry: `https://registry.npmjs.org/`
- Included files: FESM bundles, `.d.ts` declaration files, `README.md`, `LICENSE`, `package.json`
- Tarball size and file count

### B. Creating a Local Tarball (`npm pack`)
You can package the library into a `.tgz` archive for offline testing or manual verification:

```bash
npm pack ./dist/ngx-query-builder --pack-destination publish
```

This generates an archive such as `publish/argela-uxui-ngx-query-builder-22.0.0.tgz`.

To test this tarball in an external Angular project without publishing:
```bash
# In your target application
npm install /path/to/ngx-query-builder/publish/argela-uxui-ngx-query-builder-22.0.0.tgz
```

## 7. Publishing to the npm Registry

### Automated Publish Script

The recommended way to publish is via the root workspace script:

```bash
npm run publish
```

This command executes:
```bash
npm run build && cd dist/ngx-query-builder && npm publish
```

It:
1. Rebuilds the library with the production configuration to guarantee up-to-date artifacts.
2. Changes directory into `dist/ngx-query-builder/`.
3. Publishes directly from the distribution folder.

### Manual Publishing Steps

If executing manually:

```bash
# Step 1: Build library in production mode
npm run build

# Step 2: Navigate to distribution directory
cd dist/ngx-query-builder

# Step 3: Publish to npm
npm publish --access public

# Step 4: Return to root
cd ../..
```

> **Warning:** Never run `npm publish` from the repository root. The root `package.json` has `"private": true` to safeguard against publishing workspace tooling instead of the library bundle.

### Post-Publish Verification

Verify that the new version is live on the npm registry:

```bash
npm view @argela-uxui/ngx-query-builder version
npm view @argela-uxui/ngx-query-builder dist-tags
```

You can also view the package page directly at:
[https://www.npmjs.com/package/@argela-uxui/ngx-query-builder](https://www.npmjs.com/package/@argela-uxui/ngx-query-builder)

## 8. Troubleshooting & Common Issues

| Issue / Error | Cause | Resolution |
|---|---|---|
| `E403 Forbidden - PUT https://... - You cannot publish over the previously published versions` | The version specified in `projects/ngx-query-builder/package.json` has already been published. | Bump the version number in `projects/ngx-query-builder/package.json` and rebuild. |
| `E403 Forbidden - You do not have permission to publish...` | Your logged-in npm user does not belong to the `@argela-uxui` organization or lacks write permissions. | Verify active user with `npm whoami`. Request access to the `@argela-uxui` npm organization. |
| `E402 Payment Required - Scoped packages are private by default` | Scoped packages require explicit public access setting unless paying for private npm orgs. | Ensure `publishConfig.access` is set to `"public"` in `projects/ngx-query-builder/package.json` (or pass `--access public` to `npm publish`). |
| `Cannot publish a project in full compilation mode` | The library was built with `npm run build:watch` or development configuration. | Build using `npm run build` which invokes the `production` configuration (`compilationMode: "partial"`). |
| `EOTP / Two-Factor Authentication Prompt` | Account has 2FA enabled (mandatory for npm publishers). | Provide your authenticator app code when prompted. |
